# Defines

Betaflight uses `#define` macros to add software parts and hardware drivers to the firmware at build time. Most of these macros are `USE_` flags.

The [Build Options](/docs/wiki/guides/current/Build-Options) page in the wiki gives the flags that a user can set. These are the selectable build options (the lists in the Firmware Flasher tab of the Betaflight App) and the manual build options (the `Custom Defines` field). This page gives all the other `USE_` flags.

## How Flags Get Set

1. `src/main/target/common_pre.h` sets the default flags before the board configuration. For a cloud build (`CLOUD_BUILD`), the user selection replaces the defaults in the `!defined(CLOUD_BUILD)` block.
2. The board `config.h` sets the hardware flags for the board.
3. The cloud build server adds the flags that the user selects, and the related flags from its flag mappings.
4. `src/main/target/common_post.h` and `src/main/target/common_defaults_post.h` add or remove flags that depend on other flags.
5. The platform headers under `src/platform/` set the MCU flags.

:::note

Betaflight is changing from `USE_` flags to `ENABLE_` flags. A `USE_` flag is either defined or not defined (`#ifdef`). An `ENABLE_` flag has the value `0` or `1` (`#if`). Thus, you can stop an `ENABLE_` feature from the command line with `ENABLE_X=0`. When `USE_X` is defined, `common_post.h` sets `ENABLE_X` to `1`. The change occurs when the related code changes.

:::

## How To Read the Tables

- **Set by**: The file or condition that turns on the flag.
- **Introduced**: The first firmware release that has the flag. "&lt; 2025.12" means that the flag was in Betaflight 4.5 or earlier. "2026.12" means that the flag is only in the development (master) version at this time.
